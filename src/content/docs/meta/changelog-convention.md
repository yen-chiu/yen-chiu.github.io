## 记什么

只记站点本身的改动：功能、样式、修复、基建。

文章发布**不进**更新日志 —— 新文章由 RSS、归档和首页自然承担。早先几条「新增文章」的记录已经摘掉，文章本身保留。

## 版本号

- 格式 `vMAJOR.MINOR`，当前 MAJOR 固定为 `1`，写作 `v1.0`、`v1.15`。
- **一条更新 = 一个 MINOR**，按时间递增，不跳号、不复用、不回头改旧编号。
- 只有整站结构性改版才进位到 `v2.0`；日常改动一律在 `1.x` 里加。
- 数组按时间倒序排列，最新的在最前，`version` 也最大。

## 日期

- `date` 取这条更新**最后一次真实提交**的日期（`Asia/Shanghai`，`YYYY-MM-DD`），不按发稿日补、不按印象填。
- 同一件事散落在多次提交里时，合并为一条 `note`，日期取最后那一次。
- 回填方式：在站点仓库跑 `git log --since=… --pretty='%h %ad %s' --date=iso-strict`，用提交时间校准。

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `version` | 是 | `1.x`，不带 `v` 前缀，渲染时补 |
| `date` | 是 | 真实提交日期 |
| `kind` | 是 | `feature` / `fix` / `style` / `infra`，已停用 `content` |
| `scope` | 否 | `主站` / `子站` / `写作台` |
| `title` | 是 | 一句话说清这次变了什么，不加标点尾巴 |
| `note` | 否 | 一到两句讲清改动细节，避免只写「优化」 |
| `links` | 否 | 站内写 `/posts/xxx/`，站外写完整 URL；站内链接会自动加上子路径 |

## 流程

1. 改完并提交站点改动；
2. `git log` 取最后一次提交的日期；
3. 在 `src/data/changelog.json` 数组最前追加一条，`version` 取上一条 +0.1；
4. 跑 `npm run build`，确认 `/changelog` 与关于页的最近三条都正常；
5. 提交信息用 `docs(changelog): v1.x 一句话`。

## 为什么这么定

版本号是给「一次能讲清的改动」用的，不是给每次 `git commit` 用的 —— 一晚上几十个提交，对外只需要一个 `v1.11`。日期跟着真实提交走，回看时能直接对到仓库历史，不靠记忆。
