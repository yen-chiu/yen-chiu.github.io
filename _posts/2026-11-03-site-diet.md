博客跑了三年，`git clone` 越来越慢，GitHub Actions 每次部署也要多等一会儿。一直知道仓库「有点大」，但没细究。这次趁着改造，把体积问题彻底解决了一遍。

结论：**`.git` 从 390.4MB 降到 179.3MB，`assets/img` 从 167.8MB 降到 3.5MB。**

## 先找出「谁在占地方」

不要凭感觉删文件。Git 里每个对象都有大小，可以按体积排序：

```bash
git rev-list --objects --all \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' \
  | awk '/^blob/ {print $3, $4}' \
  | sort -nr \
  | head -20
```

Windows 上我是这么写的：

```powershell
git rev-list --objects --all |
  git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' |
  Where-Object { $_ -match '^blob' } |
  ForEach-Object { $p = $_ -split ' ', 4; [pscustomobject]@{ MB = [int]$p[2]/1MB; Path = $p[3] } } |
  Sort-Object MB -Descending | Select-Object -First 15
```

结果挺有意思：

| 大小 | 文件 | 这是什么 |
| --- | --- | --- |
| 90.94 MB | `_posts/images/.../PS2.txt` | 一个 Photoshop 批处理日志，没有任何引用 |
| 74.58 MB | `assets/img/avatar/liya.psd` | 头像的 PS 源文件 |
| 37.22 MB | 同名 `.psd` 的历史版本 | 同上，旧版 |
| 72.09 MB | `assets/media/*.mp4` | 一段理论微课视频 |
| 31.52 MB ×2 | `favicons/*.psd` | 网站头像源文件 |
| 22 MB | `liya*.png` 等 5 张旧头像 | 早就没用了 |

三个问题一目了然：**垃圾文本、设计源文件、未压缩的图片**。

## 第一刀：把「不会显示的东西」请出仓库

`.psd` 浏览器根本渲染不了，放在 `assets/` 下它不会出现在任何页面上，只会被原样复制进 `_site`——每次部署都往上推 100MB 无用文件。同理还有 favicon 的设计源图、旧头像、孤儿配图。

一共移出 **145.6MB**（36 个文件），同时把规则写进 `.gitignore`：

```gitignore
*.psd
*.psb
*.ai
*.sketch
*.xcf
```

> 想复用这些源文件的话，本地留一份就行，不必进版本库。

## 第二刀：图片压缩，21.8MB → 2.1MB

站点里真正被引用的图其实不多，但每张都很大：一张 4173×2592 的线稿 PNG 有 5.8MB。

压缩策略按图片类型分：

- **线稿 / 插画**（颜色数少）：转 256 色调色板 PNG，视觉几乎无损；
- **照片**（颜色数多）：等比缩到最长边 1600px，转 JPEG q85；
- 头像：3000×3000 → 480×480。

```python
im = Image.open(path)
im.thumbnail((1600, 1600), Image.LANCZOS)
if colors < 8000:
    im.quantize(colors=256, method=Image.FASTOCTREE).save(path, "PNG", optimize=True)
else:
    im.convert("RGB").save(path.replace(".png", ".jpg"), "JPEG", quality=85, optimize=True)
```

效果：

```text
avatar.png                      1014 KB ->    28 KB  ( 2.8%)
volunteer-visit/cover.png       1806 KB ->   172 KB  ( 9.5%)
street-interview.png            5950 KB ->   700 KB  (11.8%)
zhou-laoren.png                 2370 KB ->   169 KB  ( 7.1%)
papercut-neighbors.png          6447 KB ->   653 KB  (10.1%)
marxism-micro-lesson/cover.png  2308 KB ->   192 KB  ( 8.3%)
my-first-blog/first-look.png     964 KB ->    41 KB  ( 4.2%)
------------------------------------------------------
合计                            21.8 MB ->   2.1 MB
```

两张剪纸作品原来没被任何文章引用（等于白存），这次顺手加进了「记录一次志愿活动」，算是物归其用。

## 第三刀：重写历史

前面两步只是「以后不再变大」。历史里那 90MB 文本、108MB PSD 还在，`git clone` 依然要下载。要真正瘦身，只能重写历史：

```bash
# 1. 先备份所有分支和标签
git bundle create ../backup.bundle --all

# 2. 用 git-filter-repo 从所有提交里移除这些路径
python git-filter-repo --force --invert-paths --paths-from-file filter-paths.txt
```

`filter-paths.txt` 长这样（支持 `literal:` / `glob:` / `regex:`）：

```text
glob:*PS2.txt
glob:*.psd
literal:yenchiu.com.key
literal:yenchiu.com.pem
glob:assets/img/avatar/liya*
glob:assets/img/favicons/*/*
glob:assets/img/myimg/*
```

1884 个提交写完只用了 15 秒，重新打包后：

```text
重写前：390.4 MB
重写后：179.3 MB
```

剩下的 179MB 里，72MB 是还没搬走的视频，其余是三年积累的图片和上游主题的提交历史。

> 重写历史会改变所有 commit 的哈希，之后必须 `git push --force`。如果有人 fork 了你的仓库，他们的历史就和你的对不上了。所以：**先 `git bundle` 备份，再动手**。

## 结果

| 指标 | 之前 | 之后 |
| --- | --- | --- |
| `.git` 目录 | 390.4 MB | 179.3 MB |
| `assets/img` | 167.8 MB | 3.5 MB |
| 构建产物 `_site` | ~250 MB | 79.9 MB |
| `git clone` | 慢 | 明显快很多 |

## 几条教训

1. **`assets/` 下的一切都会被发布**。Jekyll 只是复制静态文件，它不知道 `.psd` 你打不开。
2. **设计源文件永远不要进仓库**。需要备份就放网盘或对象存储。
3. **先压缩再上传**。手机直出的照片 5–8MB，压到 1600px 通常只剩 200–400KB，肉眼几乎看不出差别。
4. **定期体检**。上面那条 `rev-list` 命令一年跑一次，能省下很多后悔。
5. **删文件 ≠ 减体积**。想真正变小，只有重写历史一条路——所以更要一开始就别把大文件放进来。

还剩最后一件事：那段 72MB 的视频还在仓库里。等它搬到对象存储，这个仓库才算真正轻下来。

> 补充一点：GitHub 端的旧对象不会立刻消失，服务端有自己的回收周期。如果在意，可以联系支持清理，或者直接等它自己过期。
